# Entropy Nexus Vault｜記憶寶庫

Entropy Nexus 記憶寶庫管理 App 是一套 Windows 桌面工具，用來查閱、整理主控台留下的本機記憶，以及沿著節點和專案回顧工作。

## 可以做什麼

- **樓下典藏室**有判例、決策、書籤、典藏四個書架。可依類別或書閣篩選、搜尋卷宗和節點，在待核閱案頭確認卷宗或完成書籤。閱讀桌可切換 A/B 版式，查看結論、正文、回顧和取代演化線。卷宗也可退回、移入回收區，並從當次提示撤銷。
- **樓上星象召喚盤**以水晶呈現節點與四種關係。統計檔有專案表時可進入專案星系，查看歸屬和跨星系協作。履歷欄可查經歷等級與光暈、手動頒發或撤回彩虹。側寫全文、編輯和喚醒使用 M5d 的主程序 API，履歷欄接線由 M5d-b 驗收。喚醒請求送出後，由主控台確認是否接回節點。

## 與主控台的分工

寶庫直接讀主控台寫出的本機 Markdown 記憶庫。正式版預設使用 `%APPDATA%\entropy-nexus\memory-vault`，也能透過系統對話框選擇記憶庫。主控台產生的 `.nexus-stats.json` 與 `.nexus-heat.json` 供唯讀查詢，原始專案 ID 會在主程序轉為穩定的 `p_` 代號，供篩選、連線與星系分組使用。舊統計沒有專案表時，仍可使用水晶星圖。

寶庫的寫入由使用者操作觸發。卷宗狀態及側寫正文照各自的寫入契約更新，回收使用記憶庫的 `_回收/`。`.nexus-writes.json` 由主控台維護。彩虹紀錄 `.vault-awards.json` 屬於寶庫，主控台不讀寫。介面設定、星圖與星系佈局、經歷峰值保存在寶庫的 Electron `userData`。

## 目錄

| 目錄 | 用途 |
|---|---|
| `src/main/` | Electron 主程序、記憶庫讀寫、IPC、圖像協定與系統操作 |
| `src/preload/` | 透過 `contextBridge` 提供型別化的 `window.vault` |
| `src/renderer/` | React 介面，包含典藏室、閱讀桌、星圖與星系 |
| `src/shared/` | 共用型別、IPC 契約、評分與投影等純函式 |
| `fixtures/` | 開發及契約測試用的合成或去識別記憶樣本 |
| `tests/` | 跨模組契約、建置檢查及效能量測，其他單元測試與原始碼同放 |
| `scripts/` | 建置與封裝檢查、開窗冒煙驗收 |
| `docs/` | 架構、實作計畫、審查、設計稿與發行文件 |

## 常用指令

先安裝 Node.js 22.12.0 或更新的相容版本，從 repo 根目錄執行 `npm ci`。

| 指令 | 用途 |
|---|---|
| `npm run dev` | 建置開發版到 `out-dev/` 並開啟 Electron 視窗。未選擇記憶庫時取用 `fixtures/memory-vault/`，手動驗收寫入前請選到一份複本。 |
| `npm run build:dev` | 只建置到 `out-dev/`，供開窗驗收使用。 |
| `npm run build` | 建置正式版到 `out/`。 |
| `npm test` | 執行 Vitest 單元與契約測試。 |
| `npm run typecheck` | 檢查主程序、preload 與介面型別。 |
| `npm run smoke` | 開啟 Electron 視窗，逐步驗證典藏室、寫入、回收撤銷和星圖。先執行 `npm run build:dev`。 |
| `npm run verify:build` | 檢查正式版輸出與開發標記。 |
| `npm run verify:package -- release/win-unpacked` | 檢查 Windows 封裝內容、版本、圖示及字型授權。 |
| `npm run dist` | 建置、檢查並產出 Windows NSIS 安裝程式。建置與手動驗收見 [M6 發行清單](docs/M6-發行清單.md)。 |

`smoke` 是本機手動驗收，不在 `npm test` 或 CI 中執行。它需要可開窗的桌面環境，會複製合成記憶庫、使用隔離的暫存設定，逐步輸出結果並以結束碼回報成敗。結束時關閉測試視窗並清理暫存。

## 隱私與寫入安全

- 介面只透過白名單 IPC 操作。主程序遮蔽本機絕對路徑，傳遞專案代號、相對卷宗路徑或顯示代稱。
- 私人立繪由使用者從本機選取，經 `vault-image://` 讀取。圖像路徑留在主程序，私人圖檔不入庫也不隨安裝檔發行。
- 卷宗狀態更新保留其餘原文。側寫編輯用路徑佔位符保留原文。寫入先用暫存檔，再以改名發布。主程序在寫入前與改名前核對檔案版本，遇到衝突要求重載。回收與還原會檢查目的地，避免覆蓋同名卷宗。
