## 結論

**可以合併。** 這次沒有發現會遺失資料或洩漏路徑的問題。

- **佔位符**:畫面上看不到路徑，也拿不到對照表。佔位符缺少、重複、未知或殘缺時都會擋下儲存，或先請使用者確認。
- **衝突處理**:舊文字只放在唯讀框裡，絕不會被重新送出。
- **Esc**:分層正確，每次只關最上面一層。
- **喚醒**:會先確認，送出中不能重複送出。成功時只說「已送出」，失敗時給出退路。

以下 5 點都是低嚴重度或小問題。建議第 1、2 點在下一輪順手修掉，其餘可以視情況處理。

## 發現

### 1. 低:只要正文出現 ⟦ 或 ⟧ 就永遠無法儲存
- 位置:`src/renderer/sky/profile-placeholders.ts:32`(`damaged: /[⟦⟧]/.test(rest)`)、`:37`
- 現況:去掉合法的 `⟦路徑N⟧` 之後，只要還剩任何一個 ⟦ 或 ⟧,就判定為殘缺並擋下儲存。但後端保留的只有 `⟦路徑…` 這種寫法。
- 失敗情境:側寫原本(或使用者)寫了「⟦注意⟧」這類用到白角括號的文字，編輯畫面就會一直顯示「殘缺」,而且沒有任何辦法存檔。使用者也看不出是哪個字元造成的，只能猜，把這些括號刪掉才能存。
- 建議:只把 `⟦路徑` 開頭但格式不對的片段當作殘缺，例如 `/⟦路徑(?!\d+⟧)/` 或 `/路徑\d*⟧/` 這類殘片。純粹的 ⟦…⟧ 文字就放行，交給後端驗證(後端本來就會再檢查一次)。另外補一條測試。

### 2. 低:確認刪除佔位符後如果寫入失敗，按「重試」會再問一次
- 位置:`ProfileOverlay.tsx:127–151`(`save`)、`:272`(重試按鈕走 `requestSave → save()`)
- 失敗情境:
  1. 使用者刪掉一個佔位符，按下「確認刪除並儲存」(這次會帶 `acknowledgedRemovals`)。
  2. 寫入時遇到 io 或 occupied 而失敗，畫面顯示「重試」。
  3. 按「重試」時呼叫的是 `save()`,沒有帶 acknowledged。後端回 missing,又跳出一次刪除確認。
- 影響:結果是安全的，只是同一件事被問了兩次。
- 建議:失敗時記下這次有沒有帶 `acknowledged`,重試時沿用。或者乾脆維持現狀，但在報告裡註明這是刻意的設計。

### 3. 小:衝突時保留的舊文字，裡面的佔位符編號屬於舊的工作階段
- 位置:`ProfileOverlay.tsx:110`(`setConflictText`)、`:264`(唯讀框)
- 現況:按「重新載入」會開一個新的工作階段，佔位符會重新編號。舊文字只用來複製，不會被送出，所以是安全的。
- 失敗情境:使用者把舊文字裡的 `⟦路徑2⟧` 複製貼進新版正文，可能對到另一條路徑，或被判為未知編號。如果是未知編號，會被擋下來;但如果剛好對到另一條，就會被悄悄換成錯的路徑。
- 建議:在唯讀框旁邊加一句「這段文字裡的路徑標籤屬於舊版，請不要直接貼回」。比較穩的做法是在唯讀框中把標籤顯示成「(路徑)」。

### 4. 小:第一次存檔的提示可以再完整一點
- 位置:`ProfileOverlay.tsx:18`(`saveNoticeText`)
- 現況:文字本身正確。補充一點：主控台目前的行為是，被改過的狀態會一直保留，即使之後主控台附加了內容也不會恢復成覆寫。而且附加時只會附上有變動的章節，內容和檔案裡最新版本一樣時就不寫入。
- 建議:可以改成「存檔後主控台會一直把這份側寫視為你改過:之後總管更新特長時，只會把有變動的章節附加在文末，不會覆寫你的內容。」這是文案上的取捨，不改也不算錯。

### 5. 小:「已送出」的提示會一直留到 App 重開
- 位置:`Sky.tsx:195–211`(`sendWake`)、`:276`(只在同一個 nodeId 時顯示)
- 失敗情境:
  1. 使用者喚醒成功，畫面顯示「已送出」。
  2. 但使用者後來在主控台按了取消，節點仍然是封存狀態。
  3. 之後再點同一個水晶，畫面還是顯示「已送出」,直到再按一次喚醒，或重開 App。
- 影響:這段文字本身已經說明「以下一份統計為準」,所以不算誤導。
- 建議:統計重新讀入，或換成別的節點時，把 `wakeState` 清掉。
- 另外,`requestWake` 拋出例外時被當成 `rejected`,顯示的是「沒有送出:請用開啟舊 session 接回」。這樣處理在安全上沒問題，但如果其實是 IPC 本身失敗，換成「無法聯絡主控台」會比較準確。

## 逐項檢查

1. **佔位符的規則與流程**
   - 介面只看得到 `⟦路徑N⟧`,看不到對照表。
   - 缺少編號會走「列出 → 可以復原 → 確認後帶 `acknowledgedRemovals` 重送」這條路。
   - 重複、未知或殘缺時會顯示原因並擋下儲存;復原按鈕會把標籤插回游標位置。
   - 唯一的問題見第 1 點。
2. **閱讀全文**
   - 正文、回顧、主控台補充分節顯示，時間用本機時間，並標示為唯讀。
   - 和主控台新的附加格式相容：標題是 `## 主控台補充(YYYY-MM-DD HH:mm)`,括號是半形，時間是 UTC。
   - 頁首會顯示補充的段數。
3. **喚醒**
   - 按鈕只在「封存 && canWake && detail」時出現。
   - 確認對話框預設聚焦在「取消」,這是安全的預設。
   - 送出中按鈕會停用，`onWake` 也會再擋一次。結果出來後焦點回到按鈕。
   - 失敗時會提示用「開啟舊 session」接回，並附上 sessionId。sessionId 不是路徑，顯示出來符合規格。
4. **Esc 分層與焦點**
   - `SkyDialog` 和 `ProfileOverlay` 都會 `stopPropagation`,所以星圖本身的 Esc(包括星系的兩段 Esc)不會被觸發。
   - 編輯中有未存的修改時，會先問要不要放棄，選「放棄」會回到閱讀;再按一次 Esc 才關閉閱讀紙。
   - 儲存中按 Esc 不會有反應。
   - 對話框關閉時會把焦點還回原本的元素。
   - Tab 鍵會被限制在對話框內，被 inert 的元素會略過。
5. **隱私**
   - 介面這一層沒有任何路徑字串。
   - 錯誤訊息是固定文案，不會把後端的路徑帶到畫面上。
   - 測試也檢查了畫面上沒有路徑。
6. **測試與 keeper 提出的兩個疑慮**
   - `profile-ui.test.tsx` 的 9 條測試涵蓋了上面所有流程。目前缺的是第 1 點(非保留用途的 ⟦⟧)和第 2 點(重試時要不要帶確認)的情境。
   - 「不再提示」存在 localStorage:這個設定只影響介面，清掉 App 資料後會再提示一次。真正保護使用者內容的是主控台那邊會一直保留的「被改過」狀態，不靠這個提示，所以可以接受。
   - 衝突時沒有顯示差異:目前是保留舊文字、載入新版，讓使用者自己比對。這對 M5d-b 已經夠用，差異對照可以列為之後的改進，不必擋這次合併。
