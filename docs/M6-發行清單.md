# M6 Windows 發行清單

在可連網的 Windows x64 電腦上，從要發行的版本進入 repo 根目錄，使用 PowerShell 建置。專案要求 Node.js 22.12.0 以上，可用 Node.js 22 系列符合門檻的版本及其隨附 npm。建置期間需要下載 npm 套件、Electron 執行檔及 electron-builder 所需的 Windows 打包工具。

## 建置

先關閉手上開著的免安裝版，並將上一輪要保留的發行檔移至其他位置，方便確認這次驗證的是同一批產物。

```powershell
node --version
npm --version
npm ci
npm run typecheck
npm test
npm run dist
npm run verify:package -- release/win-unpacked
```

`npm run dist` 會建置正式版、檢查正式版輸出，再建立 NSIS 安裝程式。打包時也會檢查組裝好的 ASAR。

| 產物 | 位置 |
|---|---|
| Windows x64 安裝程式 | `release/Entropy-Nexus-Vault-Setup-<version>.exe`(預設輸出位置;0.1.1 起改輸出到 `release/<version>/`,見 `docs/進度.md`)，目前版本 1.2.1(各版內容見根目錄 `CHANGELOG.md`) |
| 供檢查的免安裝目錄 | `release/win-unpacked/`，含 `Entropy Nexus Vault.exe` 及 `resources/app.asar` |
| 隨 App 附上的字型授權 | `release/win-unpacked/resources/licenses/` |

安裝檔名稱取自 `package.json` 的 `version`。Windows App ID 為 `com.entropynexus.vault`。安裝精靈預設安裝給目前使用者，並可變更安裝位置。專案目前尚未設定程式碼簽章與自動更新。

## 發行前驗收

- [ ] `npm run verify:package -- release/win-unpacked` 以結束碼 0 完成，輸出版本與這次發行一致。核對 ASAR 包含必要入口、背景、星座線符、字型，EXE 含七層圖示，另有三份字型授權。封裝檢查也會擋下開發標記、非建置目錄與多餘圖像。
- [ ] 用同一批的 NSIS 安裝程式做乾淨安裝。確認預設安裝範圍、可變更安裝位置、開始功能表圖示和 Windows 應用程式清單版本。
- [ ] 從開始功能表啟動。選擇可丟棄的合成記憶庫複本，查看樓下背景、卷宗、字型，以及樓上星盤、水晶、星座線符。確認可開啟、關閉、重新啟動。
- [ ] 廠牌立繪由使用者自行在設定選取本機資料夾。介面接線後，用合成 PNG 測試 `<vendor>/active.png` 和 `<vendor>/dormant.png`，確認設定能保留、清除後回到星座線符，有節點自己的立繪或頭像時先顯示自己的圖。發行檔與 repo 均不附私人角色圖，選取只會記住資料夾位置。
- [ ] 如要測喚醒，先啟動 Entropy Nexus 主控台完成它的首次啟動註冊。`entropy-nexus://` 由主控台負責。從寶庫對可喚醒節點送出請求後，在主控台確認是否收到。
- [ ] 升級時先安裝前一個已發行版本，保留合成記憶庫與設定，再在相同位置執行新版安裝程式。確認版本更新、設定與記憶庫選擇仍可用，且合成記憶檔內容完整。首次發行沒有舊版時，將升級欄記為未適用。
- [ ] 從 Windows 設定解除安裝。確認安裝位置的程式檔、開始功能表項目與應用程式清單項目移除，外部記憶庫複本和立繪目錄仍完整。另記錄本機設定是否保留，以便重裝時查核。

## 常見失敗

| 情況 | 處理 |
|---|---|
| Node 版本過低或 `npm ci` 報版本不符 | 核對 `node --version` 與 `npm --version`。使用符合門檻的 Node，並從同一次 checkout 使用 `package.json` 與鎖定檔，再跑 `npm ci`。 |
| Electron 或 NSIS 工具下載失敗 | 看錯誤中的下載項目與網路訊息，確認本機能連到 npm registry 與日誌所列的下載端點。連線恢復後，依失敗階段重跑 `npm ci` 或 `npm run dist`。 |
| 產物檔案遭占用 | 關閉舊的免安裝版或安裝精靈，確認相關程序已退出，再重跑 `npm run dist`。 |
| 正式版或 ASAR 檢查失敗 | 查看第一個失敗項目。確認建置使用 `npm run dist`、工作樹與發行版本一致，再重建並跑 `verify:package`。 |
| Windows 顯示未知發行者 | 目前安裝程式未設定簽章。確認安裝檔來自本次本機建置，並記錄實際提示。 |
| 安裝後缺少廠牌圖 | 確認 App 已取得使用者選擇的資料夾，檢查品牌子目錄、`active`／`dormant` 檔名與支援格式。也可清除設定重選資料夾。 |
| 喚醒連結無法開啟 | 確認主控台已完成首次啟動及協定註冊，再從寶庫重送，並到主控台確認。 |
