# 架構

Entropy Nexus Vault(記憶寶庫管理 App)的程式架構。M1 骨架照這份建立;要改這裡的邊界,先改這份文件。

## 1. 技術

| 項目 | 選擇 |
|---|---|
| 執行環境 | Electron(主程序 Node,介面 Chromium) |
| 語言 | TypeScript(strict) |
| 打包工具 | electron-vite(主程序、preload、介面三份設定一起管) |
| 介面 | React 19 + CSS Modules(設計參數用 CSS 變數,來源是 `DESIGN.md` v9) |
| 星圖 | v9 樓上的「3D」是 CSS 3D(渾天儀)+ 手寫投影 + Canvas 2D(星點、連線),**不需要 Three.js**;Three.js 只在 v2 若要真 3D 水晶折射時再評估 |
| 單元測試 | Vitest(Node 環境測主程序與共用模組,jsdom 測介面元件) |
| 安裝檔 | electron-builder(NSIS) |
| 字型 | 樓下 Noto Serif TC、樓上 Noto Sans TC(配 Segoe UI);打包進 App(OFL),不從網路載入。JetBrains Mono 只在需要等寬欄位時使用 |

> 技術選型與 v1 範圍**已確認**(使用者 2026-11-22)。

### 1.1 v1 / v2 範圍(已確認)

- **v1 = M3–M6 全包**:
  - M3 樓下唯讀:案頭、篩選(含典藏)、四種書架與卡片、熱度、頭像章、前版浮層、閱讀桌 A/B(含回顧)、搜尋(含「相符的節點」列)、`vault-image://`。
  - M4 寫入:確認/標為完成/退回、移入回收 + 撤銷、寫入失敗重試、讀取快照快取(視窗取得焦點與自己寫入後重讀)。
  - M5 樓上原版星圖:渾天儀、水晶與自動座標、四種連線、履歷欄、經歷等級與光暈、彩虹頒發、閱讀全文、編輯側寫、喚醒;鏡頭平移的樓層切換;頭像章與節點搜尋飛往樓上。
  - M6 安裝檔與試用。
- **星圖不是「v1 2D、v2 3D」**:v9 星圖本來就是純 CSS 3D + Canvas 的偽 3D,v1 直接做完整版,不需要 Three.js。舊說法作廢。
- **v2(只留延伸項)**:
  1. 逐份查看封存紀錄(履歷欄封存時間線點日期 → 以閱讀全文開啟該份)。
  2. 檔案監看自動重讀(`watch.ts` + `onVaultChanged`;v1 以「視窗取得焦點時重讀」與手動重新整理代替)。
  3. 跨專案數完全改用專案 ID(移除名稱退路;需主控台 F1 普及後)。
  4. 卷宗正文編輯(判例/決策/書籤/典藏;v9 沒有此按鈕)。
  5. 真 3D 水晶折射(屆時再評估 Three.js)。
  6. 多記憶庫切換、匯出。

## 2. 三層邊界

```
┌──────────────── 主程序 (src/main) ────────────────┐
│ 唯一能碰檔案系統與作業系統的地方                    │
│ vault/   掃描、解析、索引、監看、寫入(原子 + 衝突)│
│ images/  自訂協定 vault-image:// 提供本機圖片        │
│ wake/    開啟 entropy-nexus://wake 網址             │
│ settings 記憶庫位置、視窗大小等設定                 │
└───────────────▲───────────────────────────────────┘
                │ IPC(只走 src/shared/ipc.ts 定義的頻道)
┌───────────────┴──── preload (src/preload) ─────────┐
│ contextBridge 暴露 window.vault(型別化的 API)     │
│ 不含任何業務邏輯                                   │
└───────────────▲───────────────────────────────────┘
                │ window.vault.*
┌───────────────┴──── 介面 (src/renderer) ───────────┐
│ React;只有畫面與互動狀態                           │
│ 不能 import node:*、electron、src/main 的任何東西   │
└────────────────────────────────────────────────────┘
```

規則:

- **安全設定**:`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`;CSP 只允許 `self` 與 `vault-image:`;不開 `file://`、不載入遠端網址;`will-navigate` 與 `window.open` 一律擋下(外部連結交給 `shell.openExternal`,且只允許 `https:` 與 `entropy-nexus:`)。
- **介面拿不到路徑以外的權力**:介面只傳「記憶庫內的相對路徑」;主程序負責檢查(正規化後必須在記憶庫內、不得含 `..`、不得指向 `_` 開頭資料夾以外的附屬檔,寫入時不得指向 `.nexus-*.json`)。App 唯一可寫的附檔是自己的 `.vault-awards.json`(由專用 IPC 寫入,不接受任意路徑)。
- **共用型別**放 `src/shared/`,三層都能 import;`src/shared/` 不能 import Node 或 Electron。

## 4. IPC 介面(初版)

全部定義在 `src/shared/ipc.ts`;介面透過 `window.vault` 呼叫。

| 方法 | 說明 |
|---|---|
| `getVaultInfo()` | 目前記憶庫路徑、是否找得到、主控台是否註冊喚醒網址 |
| `chooseVault()` | 開資料夾選擇視窗,記住選擇 |
| `getBrandPortraitSettings()` | 回傳 `BrandPortraitSettings`,只有 `configured` 與顯示用 `label`。已設定的代稱為「自訂立繪資料夾」,未設定的 `label` 為 `null` |
| `chooseBrandPortraitFolder()` | 主程序開啟資料夾選擇視窗,記住實際路徑並回傳 `BrandPortraitSettings`。成功時介面遞增本頁圖像版本;取消回 `null`,版本維持 |
| `clearBrandPortraitFolder()` | 清除立繪資料夾設定,回傳未設定的 `BrandPortraitSettings`。成功時介面遞增本頁圖像版本 |
| `chooseNodePortrait(nodeId)` | M5i:為單一節點手動指定圖片。主程序開檔案選擇視窗(png/webp/jpg/jpeg),驗證副檔名、≤ 20 MiB 與檔頭簽章後**複製**進 `userData/node-portraits/`,回 `{ ok: true, customPortraitUrl }`;拒絕回 `{ ok: false, reason: 'invalid-node' \| 'unsupported' \| 'too-large' \| 'not-image' \| 'io' }`;取消回 `null`。節點須在目前星圖上。路徑不回傳 |
| `clearNodePortrait(nodeId)` | 清除該節點的手動圖片(索引項與複製檔),回 `{ ok: true, customPortraitUrl: null }` |
| `listEntries(filter)` | 卷宗清單(含熱度等級、被取代與否);篩選:種類、子類、狀態、專案、節點、是否含被取代的 |
| `readEntry(path)` | 單筆全文:屬性、正文、回顧分開回傳、取代鏈、檔案 mtime 與大小 |
| `search(query, filter)` | 全文搜尋(標題、內文、案號、關鍵字、案由、節點名;不搜回顧) |
| `searchNodes(query)` | 節點搜尋:名稱、立繪角色(主控台的 `角色` 是立繪資料夾名稱,不是職稱)、特長第一句、側寫正文(不含回顧);回傳 `NodeHit[]`(最多 50 筆,含 `avatarUrl` 與 `brand`)。小寫欄位索引每份快照建一次;頭像網址依快照快取。查詢分詞與星系總覽的節點搜尋共用 `src/shared/node-search.ts`(空白分詞、全部字詞都要出現、NFKC 正規化) |
| `listCrystals()` | 水晶清單(合併後)、連線(傳承、交辦、同席、同專案);含 `brand`(§4.2)與節點參與的 `projects`(§9.4) |
| `listGalaxies()` / `setGalaxyPromotion(projectKey, promoted)` / `arrangeGalaxies()` | 專案星系(§9.4、`DESIGN.md` 6.10);沒有 `專案表` 時 `{ enabled: false }` |
| `readCrystal(nodeId)` | 水晶詳情：側寫、統計、封存時間線、關聯卷宗、`richness`、`award`、`glow`、`projects`、`brand`。`memoirEntries` 依作者 `節點ID` 提供未被取代的回憶錄章節（§14）；`meetingEntries` 提供主持或參與的會議（§12）。 |
| `readNodeProfile(nodeId)` | 回傳 `ReadableNodeProfile` 或 `null`:來源(現役優先、否則最新封存)、正文、回顧、按標題時間分節的主控台補充與段數 |
| `readProfileForEdit(nodeId)` | 回傳 `ProfileEditResult`:可編輯正文(含使用者回顧)、編號路徑佔位符、版本、`isArchive` 與 `archiveNotice`;檔頭及主控台補充不進編輯器 |
| `saveProfileBody(nodeId, body, expectedVersion, options?)` | 只改當前側寫的使用者正文;`options.acknowledgedRemovals` 可帶上使用者確認刪除的編號。成功回新版版本;衝突只可重載,見 §10.4 |
| `setAward(nodeId, { reason } \| null, expected)` | 頒發/撤回彩虹(§9.3);`listCrystals()` 另回 `awards: { version, corrupt }` 供比對 |
| `setStatus(path, status, expected)` | 改狀態(確認/退回/書籤完成);`expected` 是讀取時的 mtime 與大小 |
| `saveEntry(path, text, expected)` | 儲存編輯後的全文 |
| `moveToRecycle(path, expected)` | 移到 `_回收/`(保留相對路徑結構) |
| `restoreFromRecycle(recycledPath, expected)` | 從回收區還原(撤銷);`expected` 是移入回收時回傳的版本 |
| `requestWake(nodeId)` | 只向主控台送出喚醒請求;未註冊或被拒時回節點名稱與 sessionId 供退路。舊 `wake(nodeId)` 通道共用同一實作 |
| 事件 `onVaultChanged(paths)` | 監看到檔案變動時推送 |

卷宗寫入方法回傳 mtime、大小與錯誤代碼。側寫編輯另使用 `ProfileEditVersion`;衝突時可重新載入或比較差異,側寫 IPC 無強制覆寫選項。

喚醒 ID 與主控台共用同一規則 `^[A-Za-z0-9_-]{1,64}$`。主程序組成 `entropy-nexus://wake?node=…`,介面無網址參數。成功文案只能寫「已送出,請到主控台確認」,主控台會再跳出確認。

### 4.2 `vault-image://` 協定

- 用途:讓介面顯示**使用者本機**的角色立繪與頭像,而不開 `file://`、不讓介面知道任意檔案路徑。
- 網址只帶**代號**,不帶路徑:`vault-image://node/<節點ID>/portrait`(水晶、履歷欄立繪)、`vault-image://node/<節點ID>/avatar`(卷宗卡頭像章、履歷欄頭像)。
- 主控台端的事實(主控台 `src/main/vault-images.ts`、`vault-stats.ts`,claudia jr 2026-11-22 查證):
  - `.nexus-stats.json` 根層有 `圖像目錄`;每個節點有 `頭像路徑`、`立繪路徑`(主控台解析好的**絕對路徑**,沒圖為 `null`)。現役節點在 `<圖像目錄>\<角色>\` 下找:頭像依序 `avatar.*`、`chibi_avatar.*`,立繪 `neutral.*`,副檔名 `png/webp/jpg/jpeg`。沒指定角色的節點兩欄都是 `null`。
  - 封存節點的這兩欄指向記憶庫內的快照 `nodes/封存/_圖像/<節點ID>/avatar.<副檔名>`、`portrait.<副檔名>`。

**解析順序(主程序,對每個代號 `node/<節點ID>/<avatar|portrait>`)**

0. **節點ID 檢查**:必須是 stats `節點` 的鍵或某份封存檔的 `節點ID`;且不得含 `/ \ :`、不得為 `.`/`..`、長度 ≤ 128。不合格 → 404。
1. **stats 路徑**:該節點在 `.nexus-stats.json` 有對應欄位(`avatar` → `頭像路徑`、`portrait` → `立繪路徑`)且不是 `null` → 套用白名單檢查,通過就回傳。
2. **封存快照**:`<記憶庫>/nodes/封存/_圖像/<節點ID>/` 下找 `avatar.*`(頭像)或 `portrait.*`(立繪),副檔名依序 `png → webp → jpg → jpeg`,第一個通過白名單的回傳。**不在 stats 裡的節點(例如已終止、統計已滾出的節點)只走這一步。**
3. **都沒有** → 404。介面的退路:卷宗頭像章 → 首字徽章(DESIGN 5.6.1);水晶與履歷欄依下列圖像順序顯示。

**白名單條件(第 1、2 步都要全部通過)**

- 以 `realpath` 解析(展開符號連結)後的檔案路徑,必須落在下列目錄之一的 `realpath` 之內:
  - stats 根層的 `圖像目錄`(stats 不存在或此欄無效時,這一項不成立);
  - `<記憶庫>/nodes/封存/_圖像/<節點ID>/`(只限**同一個**節點ID 的資料夾)。
- 是一般檔案;副檔名(不分大小寫)限 `png / webp / jpg / jpeg`;大小 ≤ 20 MiB,且檔頭簽章須符合格式。
- 任一條不符 → 視為不存在,繼續下一步(第 1 步失敗會落到第 2 步)。
- 回應:依副檔名給 `Content-Type`;`Cache-Control: no-store`;不加任何跨來源許可標頭。
- 主程序對「代號 → 檔案」的解析結果可快取,記憶庫或 stats 變動時清除。
- CSP:`img-src 'self' vault-image:`。
- 這些圖**只在本機讀取顯示**;不寫進任何快取資料夾、不送出到任何外部服務、不進 repo。

**廠牌預設立繪**

- `brandPortraitPath` 記在主程序的 `userData/settings.json`(開發用 `settings.dev.json`),預設 `null`。使用者用系統視窗選取既有資料夾,主程序存 `realpath`。磁碟根目錄不在白名單內。介面只能取得設定狀態與代稱。
- `vault-image://brand/<vendor>/<state>` 只接受 GET。`vendor` 限 `claude`、`codex`、`gemini`,`state` 限 `active`、`dormant`。此路由僅在設定資料夾的同名子目錄內依 `png → webp → jpg → jpeg` 查找固定檔名。使用上方的一般檔案、20 MiB、檔頭簽章與回應規則。展開符號連結後仍須落在設定目錄內。未設定、缺圖或所有候選皆無效時回 404。
- 廠牌網址可單獨附加 `?v=N`,`N` 限 `[1-9][0-9]*` 格式。主程序忽略該值並照常讀取當前設定資料夾。介面用本頁的正整數版本讓 Chromium 重新請求圖像,成功選擇或清除後遞增,取消與失敗時維持。IPC 回傳形狀照舊。其他查詢參數與所有片段標記回 404,節點專用圖像網址維持原規則。
- `NodeCrystal.brand` 與 `NodeHit.brand` 皆為 `{ vendor: 'claude' | 'codex' | 'gemini' | null, mode: 'active' | 'dormant' }`。主控台統計檔的 `session.後台` 值 `claude`、`codex`、`antigravity` 分別對應三家。缺少或不認得後台時 `vendor` 為 `null`。線上、現役、忙碌為 `active`,休眠、封存、終止為 `dormant`。主控台目前把忙碌與已終止分別彙整為「線上」與「封存」。
- **節點圖像顯示順序(M5i,使用者指定;水晶、履歷欄、星系內層、卡片頭像章、搜尋小章一致)**:① 使用者手動指定的圖片(`customPortraitUrl`)→ ② 廠牌預設圖(已設定資料夾且 `vendor` 有值;現役 `active`、休眠/封存 `dormant`)→ ③ 節點自己的圖(水晶與履歷欄:`portraitUrl` 再 `avatarUrl`;頭像章與搜尋小章只用 `avatarUrl`)→ ④ 星座線符(水晶、履歷欄)或節點首字(頭像章、小章)。圖像載入錯誤時前進一項。

**手動指定的節點圖片(M5i)**

- **存放**:只在寶庫 App 的 `userData`,不寫主控台記憶庫、不改 `.nexus-stats.json`、不進 repo。選擇的檔案**複製**到 `userData/node-portraits/<32 位隨機十六進位>.<png|webp|jpg>`(原檔搬移或刪除不影響);索引 `userData/node-portraits.json`:`{ "版本": 1, "記憶庫": { "<v_代號>": { "<節點ID>": { "檔案": "<隨機名>.png", "版次": n, "指定時間": ISO } } } }`。索引只存隨機檔名,不存原檔路徑或檔名。寫入:複製檔用 `wx`、索引用暫存檔 + 改名;同時只處理一個變更;索引寫入失敗時回滾並刪除新複製檔。
- **一張圖、兩種狀態共用**:不分現役/休眠兩張。理由:手動指定是使用者為該節點挑的「那一張」,休眠/封存的淡化已由水晶樣式表現;分兩張會讓操作加倍、且多數使用者只有一張圖。
- **驗證**:副檔名限 png/webp/jpg/jpeg(不分大小寫);一般檔案;≤ 20 MiB;檔頭簽章須與副檔名相符(PNG 簽章、JPEG `FF D8 FF`、WebP `RIFF…WEBP`)。不符即拒絕,不留下任何檔案,原本的指定不變。
- **協定**:`vault-image://manual/<encodeURIComponent(節點ID)>` 可附 `?v=N`(`N` 為該節點的版次,`[1-9][0-9]*`,只改快取鍵)。只接受 GET,整串網址比對;其他查詢參數、片段、多餘路徑段都回 404。主程序以目前記憶庫代號 + 節點ID 查索引,節點必須仍在目前記憶庫;只讀索引列出的那個複製檔,並沿用一般檔案、20 MiB、檔頭簽章與回應規則(展開符號連結後須仍在 `node-portraits` 內)。CSP 不變(`img-src 'self' vault-image:`)。
- **殘留**:啟動時刪除 `node-portraits/` 中沒有索引參照的檔案(例如寫入中途當機)。節點封存、改名或暫時不在記憶庫時,索引項**保留**但不顯示(封存節點仍在星圖上;節點可能再出現);要移除由使用者按「清除」。換記憶庫時各自分開(以 `v_` 代號為鍵)。
- **隱私**:IPC 只回 `customPortraitUrl`(含節點ID 與版次),不回原檔路徑、檔名或 `userData` 位置;整份回傳仍經 `redactForRenderer`。

## 10. 寫入安全(M4 審查後定案)

### 10.1 寫入流程(所有會改記憶庫檔案的動作)

1. 主程序收到路徑 → 語法檢查(`memoryPath`)→ 逐層 `realpath` 比對父資料夾(擋符號連結與 junction)→ 只允許 `cases/`、`knowledge/`、`preferences/`、`meetings/`、`memoirs/`(側寫編輯另限 `nodes/`,M5)。
2. 讀檔、重新解析,由主程序判斷這個動作是否合法(例:`canSetStatus`);不信任介面傳來的狀態。
3. 比對 `expected`(mtime + 大小);不同 → `conflict`。
4. 同資料夾建暫存檔(`.vault-write-<uuid>.tmp`,`wx` 獨佔、權限 `0o666`)→ 寫入 → `fsync`。
5. **最後一刻再比對**:mtime、大小、ino、ctime、mode 全部與步驟 2 相同才繼續。
6. `rename` 暫存檔 → 目標;Windows 上遇到 `EPERM/EBUSY/EACCES`(檔案被其他程式開著)短暫重試 25/50/100/200ms,**每次重試前重做步驟 5**。
7. 不論成功失敗,清掉暫存檔;改名後以目標檔重新 `lstat` 取回版本給介面。

回收/還原以硬連結發布到目的地(目的地已有檔案就失敗,不覆蓋),確認兩個名字指向同一檔、內容版本未變後才刪除來源;任一步失敗只刪自己建立的連結,來源保留。磁碟不支援硬連結時改用「獨佔複製 → 驗證 → 刪除來源」,失敗時刪除自己複製出的檔案。

### 10.2 殘餘時間窗:已知且接受的風險

- **App 端**:步驟 5 的最後比對到步驟 6 的 `rename` 之間仍有極小的時間窗。兩端的原子改名沒有共用鎖,若主控台在這段時間先完成改名,寶庫可能蓋掉它剛附加的「## 主控台補充」。
- **主控台端(反方向)**:主控台對「自己寫過、沒人改過」的檔案會整份取代;它檢查 `.nexus-writes.json` 與實際寫入之間若剛好被 App 改了狀態,App 的修改會被主控台蓋掉。這個空檔在主控台程式裡,App 無法消除。
- **為何接受**:
  - Windows 檔案系統沒有跨程式的「比較後交換」原語;主控台不提供鎖(已向 claudia jr 確認),加鎖要兩邊同時改協定,成本與風險高於收益。
  - 空檔是微秒到毫秒級;使用者的寫入是手動、低頻,主控台的附加也低頻,兩者撞在同一瞬間的機率極低。
  - 被蓋掉的內容都還有來源:主控台的附加來自 agent 的記憶寫入,下一次更新會再寫;App 的狀態改動,使用者在畫面上看得到結果。
- **使用者可見的後果**:
  - 大多數情況(空檔以外的同時修改)會被比對擋下,畫面顯示「未儲存 · 檔案已被修改」並提供「重新載入此卷宗」;不會覆寫。
  - 真的撞在空檔裡時:App 端看起來寫入成功;遺失的主控台附加段落會在下次總管更新時重新出現(主控台此時會因 mtime 不同而改用附加)。主控台端撞上時:重新整理後狀態回到舊值,使用者再按一次即可。

### 10.3 狀態行寫回的格式規則(S5/S6/S7 定案)

- **只改目標那一行**:`狀態` 的值;不存在時沿用 `status` 別名那一行;兩者並存只改 `狀態`;重複鍵改最後一個(與解析器一致)。其餘位元組(BOM、換行、註解、未知欄位、鍵順序、正文、非 UTF-8 位元組)原樣保留。
- **舊格式拒絕寫入**:完全沒有屬性區塊的舊卷宗,**不新增**屬性區塊,改狀態一律回 `io`,介面顯示「此舊卷宗沒有屬性區塊,請用編輯器加上 `狀態:` 後再操作」。
- **歧義拒絕**:下列情況回 `io`、檔案不變:
  - 狀態值是逐行清單、行內 `[..]` / `{..}`、區塊 `|` / `>`;
  - 屬性區塊裡沒有任何 `鍵: 值` 行(可能是正文以 `---` 水平線開頭);
  - 找不到結尾的 `---`。
- **缺少狀態欄位但有屬性區塊**:在結尾 `---` 之前插入一行 `狀態: <值>`。
- **混用換行**:插入或改寫的那一行,換行符取**相鄰行**(被改寫的那行自己的,或插入點前一行的),不取全檔第一個換行。

## 15. session 存點(2026-11-23 定稿;畫面見 `DESIGN.md` 6.6.5)

> **狀態**:使用者 2026-11-23 裁示開工;格式已由主控台 S2 定稿(`feat/session-savepoints` `85b94f9`,claudia jr 通知)。契約以主控台 `docs/session存點規劃.md` 第 5 節為準,主控台實作在 `src/main/vault-stats.ts`(`存點`、`session.可接回`)與 `src/main/wake.ts`。

**主控台寫入的東西(寶庫只讀統計檔)**
- 存點本體:`nodes/封存/_存點/<節點ID>/<YYYYMMDD-HHmmss>/`(本機時間,同一秒撞名加 `-2`、`-3`),內含 `存點.json` 與 `files/`。底線資料夾:主控台索引不收、`memory_read` 拒讀;寶庫掃描本來就跳過所有 `_` 開頭的資料夾(`scan.ts` 的 `scanFolder` 與 `memoryPath`,§5),所以 jsonl、`.db`、`brain/` 與 `存點.json` 都不會被當成記憶檔,也不在快取版本比對範圍內。
- 封存檔檔頭新增 `存點: nodes/封存/_存點/<節點ID>/<時間>`(相對記憶庫根目錄;封存檔被使用者改過時主控台不補)。寶庫**不使用**這個欄位(履歷欄以統計檔為準);解析器照常把它當一般屬性讀進來,不影響狀態行寫回。
- 記憶庫 `說明.md` 由主控台加一段說明 `_存點` 是未遮罩的原始對話。
- `.nexus-stats.json` 每個節點的 `存點` 清單(新的在前;沒有時是空清單;不帶 `工作目錄`):
  ```json
  "存點": [{ "路徑": "nodes/封存/_存點/<節點ID>/<時間>", "時間": "2026-11-23T20:00:00+08:00", "後台ID": "claude", "大小": 123, "原檔還在": null, "可還原": false }]
  ```
  - `原檔還在`:true / false / **null**。主控台直接查工具資料夾有沒有那段對話的主檔;只有節點**目前那段對話**的存點有值,舊 session 的存點是 null。快照,最多約 60 秒延遲。
  - `可還原`:已終止(資料庫有、不在面板上)、工作目錄還在、而且是節點目前那段對話的存點。在面板上的節點一律 false。
  - `session.可接回` 分階段:主控台 S3(還原流程)完成前只看原檔(原檔沒了就是 false,即使有可還原存點);S3 之後把存點算進去。統計檔與喚醒網址共用同一個判斷。
  - 封存檔被移走、`_存點` 還在時照樣列出。

**寶庫的讀法(`savepoints.ts` 解析與判定;`sidecars.ts` 呼叫解析、`crystals.ts` 掛到節點)**
- **不讀 `存點.json`,也不讀、不預覽 `files/`**;只讀統計檔的 `存點` 清單。
- 相容:
  - 舊統計檔沒有 `存點`,或 `存點` 不是陣列 → 空清單,節點其餘欄位照常。
  - 單筆格式不對就略過那一筆,不丟掉整個節點:`時間` 必須是可解析的 ISO;`路徑` 必須以 `nodes/封存/_存點/` 開頭、不含 `..` 或反斜線。
  - `原檔還在` 只收 true / false / null,其他值當 null;`可還原` 不是布林時當 false;`大小` 不是非負整數時當 null(畫面顯示「—」);`後台ID` 不是 `claude` / `codex` / `antigravity` 時記為 `other`。
  - 不認得的欄位一律忽略;1.0.0 讀到新格式不會出錯(只是不顯示存點)。
- **順序**:照統計檔的順序(新的在前),**不重新排序**,以免和主控台挑的不是同一份。
- **還原對象**(`restoreTarget`):清單中第一個 `可還原: true` 的存點,且 `canWake`(= 封存 && `session.可接回`)為 true、那一份的 `原檔還在 === false`。最多一筆;只有它在畫面上有按鈕。喚醒網址不帶存點,主控台一律還原最新一份可還原的存點,兩邊挑的是同一份。S3 上線前 `可接回` 在原檔沒了時是 false,所以不會有還原對象(預期)。

- 還原動作沿用 `requestWake(nodeId)`,不新增 IPC、不新增網路端點,寶庫不搬任何檔案。

**隱私**
