# 架構

Entropy Nexus Vault(記憶寶庫管理 App)的程式架構。M1 骨架照這份建立;要改這裡的邊界,先改這份文件。

## 1. 技術

| 項目 | 選擇 |
|---|---|
| 執行環境 | Electron(主程序 Node,介面 Chromium) |
| 語言 | TypeScript(strict) |
| 打包工具 | electron-vite(主程序、preload、介面三份設定一起管) |
| 介面 | React 19 + CSS Modules(設計參數用 CSS 變數,來源是 `DESIGN.md` v9) |
| 星圖 | v9 樓上的「3D」是 CSS 3D(渾天儀)+ 手寫投影 + Canvas 2D(星點、連線),**不需要 Three.js**;Three.js 只在 v2 若要真 3D 水晶折射時再評估 |
| 單元測試 | Vitest(Node 環境測主程序與共用模組,jsdom 測介面元件) |
| 安裝檔 | electron-builder(NSIS) |
| 字型 | 樓下 Noto Serif TC、樓上 Noto Sans TC(配 Segoe UI);打包進 App(OFL),不從網路載入。JetBrains Mono 只在需要等寬欄位時使用 |

> **暫定**:技術選型與 v1/v2 範圍仍待使用者最後確認(見 `DESIGN.md` 第 12 節);若改變,先更新這一節。

## 2. 三層邊界

```
┌──────────────── 主程序 (src/main) ────────────────┐
│ 唯一能碰檔案系統與作業系統的地方                    │
│ vault/   掃描、解析、索引、監看、寫入(原子 + 衝突)│
│ images/  自訂協定 vault-image:// 提供本機圖片        │
│ wake/    開啟 entropy-nexus://wake 網址             │
│ settings 記憶庫位置、視窗大小等設定                 │
└───────────────▲───────────────────────────────────┘
                │ IPC(只走 src/shared/ipc.ts 定義的頻道)
┌───────────────┴──── preload (src/preload) ─────────┐
│ contextBridge 暴露 window.vault(型別化的 API)     │
│ 不含任何業務邏輯                                   │
└───────────────▲───────────────────────────────────┘
                │ window.vault.*
┌───────────────┴──── 介面 (src/renderer) ───────────┐
│ React;只有畫面與互動狀態                           │
│ 不能 import node:*、electron、src/main 的任何東西   │
└────────────────────────────────────────────────────┘
```

規則:

- **安全設定**:`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`;CSP 只允許 `self` 與 `vault-image:`;不開 `file://`、不載入遠端網址;`will-navigate` 與 `window.open` 一律擋下(外部連結交給 `shell.openExternal`,且只允許 `https:` 與 `entropy-nexus:`)。
- **介面拿不到路徑以外的權力**:介面只傳「記憶庫內的相對路徑」;主程序負責檢查(正規化後必須在記憶庫內、不得含 `..`、不得指向 `_` 開頭資料夾以外的附屬檔,寫入時不得指向 `.nexus-*.json`)。
- **共用型別**放 `src/shared/`,三層都能 import;`src/shared/` 不能 import Node 或 Electron。

## 4. IPC 介面(初版)

全部定義在 `src/shared/ipc.ts`;介面透過 `window.vault` 呼叫。

| 方法 | 說明 |
|---|---|
| `getVaultInfo()` | 目前記憶庫路徑、是否找得到、主控台是否註冊喚醒網址 |
| `chooseVault()` | 開資料夾選擇視窗,記住選擇 |
| `listEntries(filter)` | 卷宗清單(含熱度等級、被取代與否);篩選:種類、子類、狀態、專案、節點、是否含被取代的 |
| `readEntry(path)` | 單筆全文:屬性、正文、回顧分開回傳、取代鏈、檔案 mtime 與大小 |
| `search(query, filter)` | 全文搜尋(標題、內文、案號;不搜回顧) |
| `listCrystals()` | 水晶清單(合併後)、連線(傳承、交辦、同席、同專案) |
| `readCrystal(nodeId)` | 水晶詳情:側寫、統計、封存時間線、關聯卷宗 |
| `setStatus(path, status, expected)` | 改狀態(確認/退回/書籤完成);`expected` 是讀取時的 mtime 與大小 |
| `saveEntry(path, text, expected)` | 儲存編輯後的全文 |
| `moveToRecycle(path, expected)` | 移到 `_回收/`(保留相對路徑結構) |
| `restoreFromRecycle(recycledPath, expected)` | 從回收區還原(撤銷);`expected` 是移入回收時回傳的版本 |
| `wake(nodeId)` | 開喚醒網址;失敗回傳節點名稱與 sessionId 供退路提示 |
| 事件 `onVaultChanged(paths)` | 監看到檔案變動時推送 |

寫入類方法的回傳一律是 `{ ok: true, mtime, size } | { ok: false, reason: 'conflict' | 'missing' | 'io', current? }`;衝突時介面跳「重新載入/仍要覆寫/比較差異」。

### 4.2 `vault-image://` 協定

- 用途:讓介面顯示**使用者本機**的角色立繪與頭像,而不開 `file://`、不讓介面知道任意檔案路徑。
- 網址只帶**代號**,不帶路徑:`vault-image://node/<節點ID>/portrait`、`vault-image://node/<節點ID>/avatar`。
- 主程序解析代號 → 實際檔案,來源只有兩種(白名單):
  1. `.nexus-stats.json` 該節點的 `立繪路徑`/`頭像路徑`(主控台已解析好的絕對路徑);
  2. 記憶庫內 `nodes/封存/_圖像/<節點ID>/` 底下的 `neutral.*`/`avatar.*`(封存快照)。
- 檢查:檔案存在、副檔名限 `png/jpg/jpeg/webp/gif`、大小上限(例如 20MB)、以 `realpath` 解析後不得是符號連結到別處的意外位置;不符一律 404。回應標頭 `Cache-Control: no-store` 以外不加任何跨來源許可。
- CSP:`img-src 'self' vault-image:`。
- **沒有立繪**(兩種來源都找不到,或檔案不合格):協定回 404,介面改顯示內建的星座線符 `assets/ui/constellation.svg`(**已定案:變體 C**,隨 App 打包、以一般靜態資源載入,不經 `vault-image://`)。
- 這些圖**只在本機讀取顯示**;不寫進任何快取資料夾、不送出到任何外部服務、不進 repo。

## 5. 與主控台的資料約定(摘要)

完整規格在主控台 repo 的 `docs/記憶設計討論.md`;這裡只列實作要遵守的:

- 記憶庫預設 `%APPDATA%\entropy-nexus\memory-vault\`,找不到讓使用者選並記住。
- 忽略 `_` 開頭的資料夾(含 `_圖像`、`_回收`)與 `*.tmp`;`.nexus-*.json` 只讀不寫。
- 附檔一次讀完立即關檔;解析失敗保留上一份。
- 寫回:暫存檔(同資料夾)+ 改名;改名前最後一刻再比對 mtime 與大小,不同就中止並回報衝突。主控台看到 mtime 改變會自動把檔案當成「使用者改過」,之後只附加不覆寫。
- `取代: [[相對路徑.md]]` 寫入時用完整相對路徑;讀取時寬鬆(省略 .md、只有檔名、`[[路徑|別名]]`)。`[[2026-0003]]` 用檔名開頭的案號反查。
- `接回自` 看屬性,也看「## 主控台補充」附加段落的第一行。
- 回顧是檔案最後的 `## 回顧` 一段,和正文分開顯示。
- **寫回不重新序列化檔頭**:`frontmatter.ts` 的解析是有損的(註解、巢狀行、引號樣式不保留)。改狀態等屬性時,直接改原始文字裡那一行(沒有就在結尾 `---` 前插入一行),其餘內容逐字保留;編輯全文時則原樣寫入使用者的文字。
- 喚醒:`entropy-nexus://wake?node=<節點ID>`,主控台會自己跳確認。

## 6. 測試策略

- `npm run typecheck`、`npm test`(Vitest 單元 + 契約)是每次修改的預設驗證。
- 會開視窗的測試(Playwright for Electron)放 `tests/e2e/`,只在使用者同意時跑。
- 時間相關邏輯(熱度衰減、相對時間)一律注入「現在時間」,測試用固定值。
