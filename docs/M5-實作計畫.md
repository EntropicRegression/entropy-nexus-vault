### 3D 投影與座標重點

- 投影(照 v10):先繞 Y 軸轉 yaw(`x1 = x cos − z sin`、`z1 = x sin + z cos`),再繞 X 軸轉 pitch(`y2 = y cos − z1 sin`、`z2 = y sin + z1 cos`);`fov = 620 × zoom`、`dist = 560`、`scale = fov / max(140, dist + z2)`;螢幕座標 `(w/2 + x1·scale, 0.52h + y2·scale)`。
- 水晶顯示:`scale' = clamp(0.62, 1.28, scale × 0.92)`;`zIndex = round(500 − z2)`;`opacity = clamp(0.45, 1, 1.05 − (z2 + 180)/720)`。
- 攝影機:yaw 初值 0.25、pitch 0.14、zoom 1;拖曳每 px 0.007 rad;pitch 限 ±0.95;zoom 0.65–1.65(每單位 0.0008)。拖曳超過 3px 才算拖曳。
- 渾天儀:`scale(zoom) rotateX(−pitch·57.3°) rotateY(yaw·57.3°)`,與水晶同步。
- 自動座標(2026-11-22 修訂):FNV-1a 初始點 → 與已存在水晶碰撞時在同層找最近空位、再換外層、最後放寬間距;結果持久化在 `userData/crystal-layout.json`,**舊水晶永遠不動**(`DESIGN.md` 6.4、`docs/架構.md` §9.1)。

## 2. rAF 動畫與測試策略

**問題**:jsdom 與無頭環境的 `requestAnimationFrame` 不會自動推進(或根本不存在),依賴 rAF 的動畫在單元測試裡不會跑完。

**原則**:把「每一幀算什麼」與「誰來推進幀」分開。

1. **純函式算狀態**(全部可單元測試,不需要 DOM):
   - `project()`、`layoutCrystals()`、`crystalStyle(projection)`(回傳 left/top/scale/zIndex/opacity);
   - 樓層切換:`floorFrame(t, direction) → { translateYvh, tiltDeg, blurY, bgParallaxPx, topbarSwapped }`,其中 `ease = t<.5 ? 4t³ : 1−(−2t+2)³/2`、`blurY = 14·sin(πt)`、`tilt = ±2.4·sin(πt)`、`topbarSwapped = t ≥ 0.45`。
   - 測試直接餵 `t = 0, 0.25, 0.45, 0.5, 1` 檢查數值(例:`t = 0.5` 時 `blurY = 14`;`t = 1` 時 `blurY = 0`、`translate` 到終點)。
2. **可注入的時鐘與排程器**:`createAnimator({ now, schedule, cancel })`,預設用 `performance.now` 與 `requestAnimationFrame`;測試注入假時鐘與手動 `tick()`,逐幀推進並斷言 DOM 樣式。不要用 `vi.useFakeTimers` 硬推 rAF(jsdom 沒有可靠的 rAF 實作)。
3. **終態必須不靠動畫也正確**:`finalizeFloor()` 直接把世界、模糊、頂列、焦點設成終態;低動態路徑與「連點跳終態」都呼叫它。單元測試以它驗證「切換後」的畫面狀態。
4. **星圖每幀迴圈**:只在攝影機變動、尺寸改變、樓上可見時排程下一幀;樓下時完全停止(省電,也讓測試穩定)。測試以手動 `tick()` 推一幀後檢查水晶樣式與 canvas 呼叫(canvas 用假的 2D context 記錄 `moveTo/lineTo/setLineDash/fillText`)。
5. **CSS 動畫**(渾天儀自轉、水晶漂浮、彩虹旋轉):jsdom 不跑 CSS 動畫,單元測試只檢查類名與低動態時的 `animation: none`;實際效果**必須開窗看**。

**開窗驗收**(需使用者同意;用 Electron 實機截圖,1600×900 與 1280×760 各一組):星圖構圖、立繪與星座線符、連線標籤不重疊、履歷欄、切換動畫的中段(約 250ms、500ms 各一張)、低動態切換。

## 4. M5b 樓層切換與跳轉

**資料與 IPC**:無新增(用 M3 的 `search` 回傳 `nodes`、M5a 的選取)。

**模組**:`src/renderer/app/{useFloorCamera.ts,floor-frame.ts}`、`App.tsx`(200vh 世界、兩層頂列、`aria-live`)、SVG 濾鏡 `<feGaussianBlur stdDeviation="0 Y">`;`src/renderer/library/NodeMatches.tsx`(相符節點列);頭像章 `onClick` → `goToNode(nodeId)`。

**行為**
- 980ms、ease-in-out cubic;`blurY = 14·sin(πt)`,結束後 `filter: none`;`rotateX ±2.4°·sin(πt)`;背景視差 `(y+100)×0.35px`;45% 交叉淡換頂列;連點跳終態;切換前關閉閱讀桌;結束後焦點移到新樓層第一個控制;`aria-live` 播報。
- 低動態/系統減少動態:120ms 淡出淡入(總長 ≤150ms)。
- `goToNode(nodeId)`:切到樓上 → **切換結束後**選中水晶並打開履歷欄;節點不存在時不切換、提示「星圖上找不到這個節點」。
- 關聯卷宗「前往圖書館 →」:切到樓下 → 結束後開啟該卷。

**驗收標準**
- 自動測試:`floorFrame` 各 t 值;`finalizeFloor` 的終態(transform、filter 清除、頂列、焦點、`aria-live` 文字);連點時第二次直接終態;低動態不建立模糊濾鏡;`goToNode` 在切換結束(手動推進假時鐘)後才選取;相符節點列最多 6 枚 + `+N`、Enter 可觸發。
- 開窗:中段截圖可見 Y 向模糊與傾斜、結束無殘留模糊;頂列交換時沒有閃爍;低動態切換。

**風險與依賴**:SVG 濾鏡套在 200vh 的整個世界上,在大解析度/低階顯示卡可能掉幀(量測 2560×1440;必要時只模糊背景層,內容層改用 opacity);M5a 的星圖迴圈要在切換期間暫停水晶更新以省成本。

## 9. M5 最大的三個風險

1. **編輯側寫寫壞使用者的節點履歷**:v1 唯一會整段改寫正文的功能;檔頭拼接、編碼、換行或主控台補充段落的拆分出錯,都會直接毀損一份側寫或封存。緩解:寫回只允許「原始檔頭位元組 + 新正文」,衝突一律拒絕,位元組級測試覆蓋 BOM/CRLF/非 UTF-8,第一次儲存前提示。
2. **樓層切換動畫的效能與可測性**:整個 200vh 世界套 SVG Y 軸模糊 + 3D 傾斜,低階顯示卡或高解析度可能掉幀;rAF 在測試環境不推進,容易寫出「看起來有測、其實沒跑」的測試。緩解:動畫數學全部做成純函式、終態函式獨立、可注入時鐘;量測不達標就只模糊背景層。
3. **經歷等級依賴主控台資料的品質**:預設驗收、180 天窗口、專案只有名稱,使等級可能與使用者直覺不符(例如舊節點掉級、同名專案合併);立繪與頭像路徑也依賴主控台 stats 的正確性。緩解:計分以已確認判例為主、完成數用本機峰值、跨專案優先專案ID(主控台 F1);徽記懸停顯示分數組成,讓使用者看得懂等級從哪來。
